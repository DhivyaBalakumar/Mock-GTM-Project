# Start here

This is a practice project that shows, end to end, what a **GTM (go-to-market) engineer** builds
and runs. Read these documents in order. Each one answers one question.

| # | Document | The question it answers | Time |
| --- | --- | --- | --- |
| 1 | [01_big_picture.md](01_big_picture.md) | What is this job, what problem does it solve, and where does this project fit? | 15 min |
| 2 | [02_day_to_day.md](02_day_to_day.md) | What does a GTM engineer actually do on a Monday, a Tuesday, a bad Friday? | 15 min |
| 3 | [03_architecture.md](03_architecture.md) | How do the pieces of this project connect, and why is it designed this way? | 15 min |
| 4 | Run it: [../README.md](../README.md) | See it working on your own laptop | 20 min |
| 5 | [04_code_walkthrough.md](04_code_walkthrough.md) | What does every file and every important line do? | 60 min |
| 6 | [05_concepts_explained.md](05_concepts_explained.md) | What do APIs, rate limits, upserts, webhooks, idempotency etc. really mean, using this code? | 45 min |
| 7 | [06_runbook.md](06_runbook.md) | How is a system like this operated: scheduled, monitored, fixed when it breaks? | 20 min |
| 8 | [08_exercises.md](08_exercises.md) | Break it, extend it, rebuild it: the practice that makes it stick | hours |
| 9 | [07_interview_talk_track.md](07_interview_talk_track.md) | How do I explain all this in an interview, and what will they ask? | 30 min |

**The goal:** after working through this, you can draw the system from memory, explain every
design decision, predict what breaks and how to fix it, and build a similar one yourself from
an empty folder.

**A note on honesty:** this is a practice project with fake data and a fake API server. Describe
it that way. What you *learn* from it is real, and the second project you build yourself with
real APIs is what you show as your own work.
